═══════════════════════════════════════════════════════════════
  CÓMO EJECUTAR — Sistema Odontológico Senza
  Archivo: docs/running.txt
═══════════════════════════════════════════════════════════════

ESTRUCTURA DEL PROYECTO
────────────────────────
  turnero-app/
  ├── frontend/ ← FRONTEND  (Angular, TypeScript)
  ├── backend/  ← BACKEND   (Node.js, TypeScript, Socket.IO)
  └── docs/     ← Documentación (este archivo)


REQUISITOS PREVIOS
──────────────────
  - Node.js instalado
  - MongoDB corriendo localmente (puerto 27017)
  - Docker (para Keycloak, puerto 8080)
  - Dos terminales abiertas al mismo tiempo


═══════════════════════════════════════════════════════════════
  PRIMERA VEZ (solo hacer esto una vez)
═══════════════════════════════════════════════════════════════

1. Instalar dependencias del backend:

      cd backend
      npm install

2. Instalar dependencias del frontend:

      cd frontend
      npm install

3. Cargar los profesionales en la base de datos:

      cd backend
      npm run seed

   Crea los 14 profesionales y la "Sede Central" en MongoDB (senza_sistema).
   No hace falta repetirlo a menos que reinstales la base.

4. Levantar Keycloak (importa el realm `senza` desde keycloak/realm-senza.json):

      docker compose up -d

   Consola de Keycloak: http://localhost:8080  (admin / admin, realm master)

5. En backend/.env, el secreto del cliente `turnero-backend` que importa
   docker-compose.yml (por defecto en desarrollo):

      KEYCLOAK_ADMIN_CLIENT_SECRET=dev-turnero-backend-secret

6. Primer ingreso a la app: usuario `admin`, contraseña temporal `CambiarEsto123`
   (Keycloak obliga a cambiarla). Desde Administración → Usuarios se crean
   los demás usuarios (odontólogos, secretarias) con contraseña temporal.


═══════════════════════════════════════════════════════════════
  EJECUCIÓN NORMAL (cada vez que querés usar el sistema)
═══════════════════════════════════════════════════════════════

TERMINAL 1 — Backend (API)
──────────────────────────
      cd backend
      npm start

  El servidor arranca en: http://localhost:3001
  Requiere que MongoDB y Keycloak estén corriendo antes.


TERMINAL 2 — Frontend (App)
────────────────────────────
      cd frontend
      npm start

  La app Angular abre en: http://localhost:4300
  Abrir esa URL en el navegador.


═══════════════════════════════════════════════════════════════
  QUÉ HACE CADA COMANDO
═══════════════════════════════════════════════════════════════

  Desde backend/:
    npm run start       → Inicia el servidor en modo desarrollo (hot-reload)
    npm run start:prod  → Inicia el servidor desde dist/ compilado (producción)
    npm run build       → Compila el backend TypeScript a dist/
    npm run seed        → Carga los 14 profesionales en MongoDB (1 sola vez)
    npm run migrate:queue → Simula la migración de la cola a queueentries
                            (agregar -- --apply para escribir; hacer backup antes)

  Desde frontend/:
    npm run start   → Inicia el frontend Angular en dev (puerto 4300)
    npm run build   → Compila el frontend para producción


═══════════════════════════════════════════════════════════════
  BASES DE DATOS MONGODB
═══════════════════════════════════════════════════════════════

  senza_sistema  → Base del nuevo sistema (profesionales, cola de espera)
  senza_totem    → Base del tótem legacy (solo lectura, no se modifica)


═══════════════════════════════════════════════════════════════
  ENDPOINTS PRINCIPALES DE LA API
═══════════════════════════════════════════════════════════════

  GET  http://localhost:3001/api/v1/health            → Estado del servidor
  GET  http://localhost:3001/api/v1/professionals     → Lista de profesionales
  GET  http://localhost:3001/api/v1/queue             → Cola activa
  POST http://localhost:3001/api/v1/queue             → Agregar paciente
  GET  http://localhost:3001/api/v1/auth/me           → Usuario actual (rol, sede, profesional)
  *    http://localhost:3001/api/v1/users             → ABM de usuarios (solo admin)
  *    http://localhost:3001/api/v1/sedes             → Sedes (escritura solo admin)

  Todo salvo /health y el tótem requiere `Authorization: Bearer <token de Keycloak>`.

  Endpoint para el tótem:
  POST http://localhost:3001/api/v1/integrations/totem/patient


═══════════════════════════════════════════════════════════════
  VARIABLES DE ENTORNO (backend/.env)
═══════════════════════════════════════════════════════════════

  PORT=3001
  MONGODB_URI=mongodb://localhost:27017/senza_sistema
  TOTEM_MONGODB_URI=mongodb://localhost:27017/senza_totem
  TOTEM_API_KEY=<clave compartida, igual en el tótem>
  CORS_ORIGIN=http://localhost:4300
  NODE_ENV=development
  KEYCLOAK_URL=http://localhost:8080
  KEYCLOAK_ISSUER=<opcional; por defecto KEYCLOAK_URL/realms/KEYCLOAK_REALM>
  KEYCLOAK_REALM=senza
  KEYCLOAK_ADMIN_CLIENT_ID=turnero-backend
  KEYCLOAK_ADMIN_CLIENT_SECRET=<secreto del cliente turnero-backend>   (obligatorio)



═══════════════════════════════════════════════════════════════
  PRODUCCIÓN (Docker + VPS)
═══════════════════════════════════════════════════════════════

  Cada push a master: GitHub Actions construye la imagen
  (Dockerfile en la raíz), la sube a ghcr.io/gonzalo32/turnero-app
  y actualiza el servidor por SSH.

  Configuración inicial del servidor (una sola vez):
    1. VPS Ubuntu 24.04 → curl -fsSL https://get.docker.com | sh
    2. DNS: registros A de tu-dominio.com y auth.tu-dominio.com → IP del VPS
    3. ufw allow 22,80,443/tcp && ufw enable
    4. Copiar a ~/turnero: deploy/docker-compose.yml, deploy/Caddyfile
       y keycloak/realm-senza.json
    5. Crear ~/turnero/.env (cada secreto: openssl rand -hex 32):
         DOMAIN=tu-dominio.com
         NODE_ENV=production
         PORT=3001
         MONGODB_URI=mongodb://mongo:27017/senza_sistema
         TOTEM_API_KEY=<secreto>
         KEYCLOAK_ADMIN_CLIENT_SECRET=<secreto>
         KEYCLOAK_DB_PASSWORD=<secreto>
         KEYCLOAK_BOOTSTRAP_ADMIN_USERNAME=<usuario consola Keycloak>
         KEYCLOAK_BOOTSTRAP_ADMIN_PASSWORD=<secreto>
         KEYCLOAK_APP_ADMIN_PASSWORD=<contraseña temporal del admin de la app>
       (KEYCLOAK_URL, KEYCLOAK_ISSUER y CORS_ORIGIN los arma docker-compose.yml)
    6. Secrets del repo en GitHub: SSH_HOST, SSH_USER, SSH_KEY
    7. Paquete ghcr.io público, o en el VPS: docker login ghcr.io
    8. Primer deploy: push a master (o "Run workflow" en Actions)
    9. Seed (una vez): docker compose exec turnero node dist/seeds/seed.js
   10. Primer ingreso en https://tu-dominio.com: usuario `admin` con
       KEYCLOAK_APP_ADMIN_PASSWORD (Keycloak obliga a cambiarla).

  Keycloak:
    - El realm se importa SOLO la primera vez (si no existe). Cambios
      posteriores al realm se hacen desde la consola de administración.
    - La consola no está publicada en Internet. Acceso por túnel SSH:
        ssh -L 8080:localhost:8080 usuario@vps
        → http://localhost:8080/admin/  (KEYCLOAK_BOOTSTRAP_ADMIN_*)
    - Rotar KEYCLOAK_ADMIN_CLIENT_SECRET: regenerarlo en la consola
      (Clients → turnero-backend → Credentials), actualizar .env y
      docker compose up -d turnero.

  El tótem debe apuntar a https://tu-dominio.com y enviar el header
  x-totem-api-key con el mismo valor de TOTEM_API_KEY.
